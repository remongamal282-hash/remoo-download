# وثيقة التصميم الهندسي لمشروع Remo Download
## الفصل 1: الرؤية والنطاق (Vision & Scope)

**رقم الوثيقة:** SDS-01
**الحالة:** مكتملة ومراجعة مبدئيًا
**آخر تحديث:** 30 يوليو 2026

---

## 1.1 المقدمة

Remo Download مشروع مفتوح المصدر يهدف لبناء مدير تحميل (Download Manager) بمستوى احترافي عالمي، يوازي أو يتفوق على Internet Download Manager (IDM) من حيث الوظائف، مع الحفاظ على كونه مجانيًا بالكامل ومفتوح الكود، ويعمل على Windows وmacOS.

المشروع مبني بلغة **C++** لمحرك التحميل والواجهة (عبر Qt6)، مع إضافة متصفح (WebExtension) للتكامل مع Chrome/Edge/Firefox/Safari.

## 1.2 المشكلة التي يحلها المشروع

- برامج مثل IDM مدفوعة (Shareware) وتقتصر على Windows فقط.
- البدائل المجانية الموجودة (مثل Free Download Manager أو JDownloader) إما بطيئة، أو واجهتها ضعيفة، أو لا تدعم كل ميزات IDM (خصوصًا الالتقاط التلقائي من المتصفح وإعادة الاتصال الذكية).
- لا يوجد حاليًا مدير تحميل مفتوح المصدر بالكامل، يدعم Windows وmacOS بنفس الجودة، ومبني بلغة نظامية (C++) توفر أداءً عاليًا واستقرارًا حقيقيًا.

## 1.3 رؤية المشروع (Vision Statement)

> "أن يكون Remo Download المرجع المفتوح المصدر الأول عالميًا لإدارة التحميلات — بأداء يوازي أفضل الحلول التجارية، وشفافية كاملة في الكود، ومجتمع مطورين نشط يطوّره باستمرار."

## 1.4 الجمهور المستهدف (Target Users)

| الفئة | الاحتياج |
|---|---|
| مستخدمون عاديون | تحميل أسرع وأكثر استقرارًا من تحميل المتصفح المباشر |
| منشئو محتوى / باحثون | تحميل دفعات كبيرة من الملفات (Batch)، ملفات كبيرة الحجم |
| مطورون ومساهمون مفتوحو المصدر | كود منظم وموثّق يسهل المساهمة فيه |
| شركات صغيرة (لاحقًا) | نسخة قابلة للتوزيع الداخلي (Enterprise/Silent Install) |

## 1.5 نطاق النسخة الأولى (Scope — v1.0)

### داخل النطاق (In Scope)
- محرك تحميل متعدد الاتصالات مع استئناف كامل.
- واجهة سطح مكتب على Windows وmacOS.
- إضافة متصفح لالتقاط الروابط والفيديوهات تلقائيًا.
- الجدولة، قوائم الانتظار، الفئات، الإعدادات المتقدمة.
- دعم HTTP/HTTPS/FTP/FTPS.

### خارج النطاق حاليًا (Out of Scope for v1.0 — مؤجل لإصدارات لاحقة)
- دعم BitTorrent/Magnet links (يُدرس في v2.0).
- تطبيق موبايل مرافق (Remote control app).
- مزامنة قائمة التحميلات عبر السحابة (Cloud Sync).
- دعم Linux الرسمي (المجتمع يمكنه البناء يدويًا، لكن لا دعم رسمي في v1.0).

> **سبب الاستبعاد المؤقت:** التركيز في النسخة الأولى على الاستقرار والجودة في وظيفتين أساسيتين (التحميل + التكامل مع المتصفح) بدلاً من تشتيت الجهد على ميزات ثانوية، تماشيًا مع مبدأ "MVP قوي أفضل من منتج متكامل ضعيف".

## 1.6 معايير النجاح (Success Criteria)

| المعيار | الهدف القابل للقياس |
|---|---|
| الأداء | تحميل بسرعة تعادل 90%+ من سرعة IDM على نفس الشبكة |
| الاستقرار | لا فقدان بيانات تحميل عند إغلاق الجهاز/انقطاع النت في 99% من الحالات |
| التوافق | يعمل على Windows 10/11 وmacOS 12+ |
| المجتمع | نشر علني على GitHub + توثيق كافٍ لاستقبال مساهمات خارجية |
| التبني | إصدار v1.0 مستقر خالٍ من الأعطال الحرجة (Critical Bugs) |

## 1.7 المخاطر الرئيسية (Key Risks)

| الخطر | التأثير | خطة التخفيف |
|---|---|---|
| رفض متاجر الإضافات (Chrome/Firefox) للإضافة بسبب اعتراض التحميلات | متوسط-عالي | الالتزام الصارم بسياسات المتاجر، توثيق واضح للصلاحيات المطلوبة |
| صعوبة تنفيذ التحميل متعدد الأجزاء بشكل موثوق مع كل أنواع الخوادم | عالي | خوارزمية fallback للخوادم التي لا تدعم Range requests (تحميل بخيط واحد) |
| Code Signing / Notarization على macOS (تكلفة ووقت) | متوسط | حساب مطور Apple مبكرًا في الخطة + أتمتة عملية التوقيع في CI/CD |
| تشتت جهد المتطوعين مفتوحي المصدر | متوسط | Backlog منظم بالأولوية + قوالب Issues واضحة (انظر الفصل 8) |

## 1.8 الافتراضات (Assumptions)

- المستخدم لديه اتصال إنترنت يدعم Range requests في أغلب الحالات (معظم خوادم الويب الحديثة تدعمها).
- سيتم استخدام تراخيص مفتوحة المصدر متوافقة مع libcurl وQt وOpenSSL (كلها تراخيص متوافقة مع GPL/MIT/LGPL).
- الفريق الأساسي يبدأ صغيرًا (1-3 مطورين) ثم يتوسع عبر مساهمات المجتمع.
