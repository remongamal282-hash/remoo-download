# Remoo Download v0.5 - Browser Integration Release

**Release Date:** January 2025  
**Status:** Ready for Manual Verification

## 🎯 Overview

Version 0.5 introduces **browser integration** for Remoo Download. Users can now automatically intercept downloads from Chrome and Edge browsers, sending them directly to Remoo Download for faster, resumable downloads.

This release implements the complete chain:
```
Browser Click → Extension → Native Host → IPC → Service → Download Engine → File on Disk
```

---

## ✨ New Features

### 1. Native Messaging Host (`remo_native_host.exe`)

A lightweight executable that bridges browser extensions with the Remoo Download service:

- **Reads Native Messaging Protocol:** Decodes 4-byte length-prefixed JSON messages from browser
- **Connects to Service:** Uses existing Named Pipe IPC (`\\.\pipe\remo_download_ipc`)
- **Forwards Downloads:** Transforms browser messages into `addDownload` commands
- **Returns Responses:** Sends success/error status back to browser

**Implementation:** `src/browser/native_host_main.cpp`

### 2. Browser Extension (Chrome/Edge)

A Manifest V3 WebExtension that intercepts downloads intelligently:

**Features:**
- ✅ **Smart Interception:** Configurable file size and extension filters
- ✅ **User Control:** Enable/disable toggle, customize settings
- ✅ **Status Display:** Real-time connection status to native host
- ✅ **Context Menu:** "Download with Remoo Download" option on right-click
- ✅ **Notifications:** User feedback for download start, errors, service status
- ✅ **Privacy-First:** No data collection, all communication is local

**Files:**
- `extensions/chromium/manifest.json` - Extension manifest (v0.5.0)
- `extensions/chromium/src/background.js` - Service worker with connection management
- `extensions/chromium/src/popup.html/js/css` - User interface with status indicator

### 3. Registration Tool

PowerShell script for easy setup:

```powershell
tools\register_native_host.ps1
```

**Capabilities:**
- Registers native host with Chrome and Edge
- Creates Windows Registry entries automatically
- Supports custom extension IDs
- Stores manifest permanently in `%LOCALAPPDATA%`
- Unregistration support with `-Unregister` flag

### 4. Comprehensive Testing

**Unit Tests (12 tests):**
- Native Messaging protocol encoding/decoding
- Little-endian length prefix validation
- Error handling for malformed messages

**Integration Tests (10 tests):**
- IPC connection with mock service
- Request format validation
- Edge cases (empty URLs, special characters, long URLs)
- Service unavailability handling

**Test File:** `tests/unit/test_native_messaging_protocol.cpp`, `test_native_host_integration.cpp`

## 🏗️ Architecture

### Component Interaction

```
┌─────────────┐
│   Browser   │ (Chrome/Edge)
└──────┬──────┘
       │ Native Messaging Protocol
       │ (4-byte length + JSON)
       ▼
┌──────────────────┐
│ remo_native_host │ (New in v0.5)
└──────┬───────────┘
       │ Named Pipe IPC
       │ (\\.\pipe\remo_download_ipc)
       ▼
┌─────────────────┐
│  remo_service   │ (Existing from v0.4)
└──────┬──────────┘
       │
       ▼
┌──────────────────┐
│ DownloadEngine   │ (Existing from v0.1-v0.4)
└──────┬───────────┘
       │
       ▼
   [File on Disk]
```

### Data Flow Example

1. **User clicks download link** in browser (e.g., `https://example.com/file.zip`)
2. **Extension intercepts** via `chrome.downloads.onCreated`
3. **Extension checks filters** (file size ≥ 10MB, extension in whitelist)
4. **Extension cancels** browser download
5. **Extension sends message** to native host:
   ```json
   {
     "type": "addDownload",
     "url": "https://example.com/file.zip",
     "filename": "file.zip",
     "source": "chromium"
   }
   ```
6. **Native host transforms** to service command:
   ```json
   {
     "command": "addDownload",
     "url": "https://example.com/file.zip",
     "filename": "file.zip"
   }
   ```
7. **Service receives** and starts download
8. **DownloadEngine** downloads file to disk
9. **Response flows back** to browser (success/error)
10. **User sees notification** "Download Started"

## 📦 Installation & Usage

### For Developers

1. **Build the project:**
   ```cmd
   cmake --preset mingw-debug -DBUILD_CLI=ON -DBUILD_TESTS=ON
   cmake --build --preset mingw-debug
   ```

2. **Run tests:**
   ```cmd
   .\build\bin\remo_tests.exe
   ```

3. **Start service:**
   ```cmd
   .\build\bin\remo_service.exe
   ```

4. **Register native host:**
   ```powershell
   powershell -ExecutionPolicy Bypass -File tools\register_native_host.ps1
   ```

5. **Load extension:**
   - Open `chrome://extensions`
   - Enable Developer Mode
   - Load Unpacked → `extensions\chromium`
   - Copy Extension ID

6. **Re-register with real ID:**
   ```powershell
   powershell -ExecutionPolicy Bypass -File tools\register_native_host.ps1 -ExtensionId "YOUR_ID"
   ```

7. **Restart browser** and test!

### For End Users (Future)

Once released to Chrome Web Store:
1. Install extension from store
2. Download and run Remoo Download installer
3. Installer handles native host registration automatically
4. Downloads automatically route through Remoo Download

## 🔒 Privacy & Security

### Privacy Commitments

- ✅ **No Data Collection:** Extension does not collect any personal information
- ✅ **No Analytics:** No telemetry or usage tracking
- ✅ **No External Connections:** All communication is local (browser ↔ local app)
- ✅ **No Browsing History:** Only sees download URLs when explicitly triggered
- ✅ **Open Source:** Complete source code available for audit

See `extensions/chromium/PRIVACY_POLICY.md` for full policy.

### Security Considerations

- Native host only accepts connections from registered extension IDs
- All communication uses Windows Named Pipes (localhost only)
- No network-accessible interfaces
- Extension runs in isolated Chrome sandbox
- User controls what gets intercepted (size, extensions, enable/disable)
