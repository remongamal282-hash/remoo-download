## 9.2 خطة الإصدار التجريبي v0.1 (Alpha)

### الهدف
التحقق من صحة المحرك الأساسي للتحميل وضمان عمل التحميل متعدد الاتصالات بشكل موثوق.

### الميزات المدرجة
- [x] هيكل المشروع الأساسي (CMake, مصدر، توثيق)
- [x] DownloadEngine مع libcurl multi-interface
- [x] التحميل متعدد الاتصالات (Segmented Download)
- [x] إيقاف واستئناف التحميل (Pause/Resume)
- [x] إعادة الاتصال التلقائي (Auto-Reconnect)
- [x] Fallback للخوادم التي لا تدعم Range
- [x] تخزين SQLite للبيانات الوصفية
- [x] Checkpoint دوري
- [x] اختبارات الوحدة الأساسية

### معايير النجاح
- تحميل ملف واحد بسرعة تعادل 80%+ من سرعة التحميل المباشر
- استئناف ناجح بعد إغلاق البرنامج
- إعادة اتصال ناجحة بعد انقطاع الشبكة
- 0 أعطال حرجة في الاختبارات

### المخاطر
- تعقيد تنفيذ التحميل متعدد الاتصالات مع خوادم مختلفة
- مشاكل توافق libcurl مع بعض الخوادم

## 9.9 معايير الإصدار (Release Criteria)

### معايير الإصدار المستقر (Stable Release)
1. جميع اختبارات الوحدة تمر بنجاح (100%)
2. تغطية الكود ≥ 80% للوحدات الأساسية
3. لا توجد أعطال حرجة (Critical Bugs) مفتوحة
4. لا توجد أعطال عالية الأولوية (High Priority Bugs) مفتوحة
5. جميع الميزات في النطاق مُنفذة ومُختبرة
6. التوثيث محدّث بالكامل
7. Code Signing مُنجز (Windows + macOS)
8. ملاحظات الإصدار مكتوبة
9. مراجعة الكود من مطورين اثنين على الأقل

### معايير الإصدار التجريبي (Pre-release)
1. جميع اختبارات الوحدة تمر بنجاح
2. لا توجد أعطال حرجة مفتوحة
3. الميزات الجديدة مُنفذة واختُبرت
4. التوثيق الأساسي محدّث

## 9.10 عملية الإصدار (Release Process)

1. **تجميد الميزات (Feature Freeze):** إغلاق باب إضافة ميزات جديدة قبل الإصدار بأسبوعين
2. **مرحلة الاختبار (Testing Phase):** اختبارات شاملة + اختبارات انحدار
3. **إصلاح الأعطال (Bug Fix):** إصلاح جميع الأعطال عالية الأولوية
4. **تحديث التوثيق:** تحديث README وملاحظات الإصدار
5. **بناء الإصدارات:** بناء لجميع المنصات
6. **Code Signing:** توقيع الإصدارات
7. **إنشاء Release:** نشر على GitHub مع ملاحظات الإصدار
8. **الترويج:** إعلان على وسائل التواصل والمجتمعات
9. **التحديث:** دمج الفرع مع `main` و `develop`
