# وثيقة التصميم الهندسي لمشروع Remoo Download
## الفصل 9: خطة الإصدارات (Release Roadmap) من v0.1 حتى v2.0

**رقم الوثيقة:** SDS-09 (الفصل الأخير)
**يعتمد على:** كل الفصول من SDS-01 حتى SDS-08

---

## 9.1 فلسفة الإصدارات

Remoo Download يتبع **Semantic Versioning** (`MAJOR.MINOR.PATCH`):
- **MAJOR (مثل v2.0):** تغييرات معمارية كبرى أو ميزات جوهرية جديدة (BitTorrent، تطبيق موبايل).
- **MINOR (مثل v1.1):** ميزات جديدة متوافقة مع الإصدار السابق.
- **PATCH (مثل v1.0.1):** إصلاحات أخطاء فقط، بلا ميزات جديدة.

كل إصدار له **معايير خروج (Exit Criteria)** واضحة — لا ينتقل المشروع للإصدار التالي إلا بعد تحقيقها، تفاديًا لتراكم الديون التقنية.

## 9.3 v0.1 — نواة التحميل (Core Engine Foundation)

**الهدف:** إثبات أن محرك التحميل الأساسي يعمل ويُختبر، عبر واجهة سطر أوامر (CLI) بسيطة فقط، **بدون أي واجهة رسومية أو متصفح بعد** — تقليل المخاطر عبر التحقق من أصعب جزء تقني أولًا (مبدأ "Walking Skeleton").

**المهام المرتبطة (من الفصل 8):** 1.1 - 1.8، 2.1 - 2.9، 2.11، 2.24، 9.1 - 9.3

**النطاق الوظيفي:**
- تحميل ملف واحد عبر HTTP/HTTPS بتعدد الاتصالات.
- تقسيم الأجزاء الأساسي (بدون إعادة التوازن الديناميكي بعد).
- دمج الأجزاء والتحقق الأساسي من اكتمال الحجم.

**معايير الخروج (Exit Criteria):**
- [ ] تحميل ملف اختباري بحجم 1GB بنجاح عبر CLI مع تعدد اتصالات.
- [ ] تغطية اختبارات وحدة ≥ 70% لمحرك التحميل.
- [ ] CI أخضر بالكامل على Windows وmacOS.

## 9.4 v0.2 — الاستئناف وإعادة الاتصال والاستقرار

**الهدف:** الوصول للاستقرار الحقيقي الذي يميز مدير تحميل احترافي عن سكربت تحميل بسيط.

**المهام المرتبطة:** 2.10، 2.12 - 2.17، 2.25، 2.26، 3.1 - 3.8، 3.14، 3.15، 9.4، 9.5، 9.8

**النطاق الوظيفي:**
- إيقاف/استئناف كامل مع Checkpoint دوري.
- إعادة الاتصال التلقائي مع Exponential Backoff.
- استكمال بعد إعادة تشغيل التطبيق بالكامل (Crash Recovery حقيقي).
- SQLite كطبقة حفظ فعلية بدل ملفات مؤقتة.

**معايير الخروج:**
- [ ] قطع الاتصال يدويًا أثناء اختبار آلي، والتحقق من الاستئناف التلقائي دون فقدان بيانات.
- [ ] قتل العملية (Force Kill) أثناء تحميل نشط، والتحقق من استكمال ناجح بعد إعادة التشغيل.
- [ ] بناء ASan/UBSan نظيف بالكامل (بلا تسريبات ذاكرة).

## 9.5 v0.3 — الخدمة الخلفية والتواصل الداخلي

**الهدف:** الانتقال من "برنامج CLI واحد" إلى المعمارية النهائية (Service منفصلة عن الواجهات).

**المهام المرتبطة:** 4.1 - 4.8، 4.18، 9.6

**النطاق الوظيفي:**
- `remo-service` يعمل كخدمة/daemon خلفية حقيقية.
- قناة IPC كاملة (Named Pipes/Unix Sockets + Protobuf).
- Queue Manager بأولويات.

**معايير الخروج:**
- [ ] الخدمة تستمر بالعمل وتُكمل تحميل نشط حتى مع عدم وجود أي عميل (Client) متصل.
- [ ] اختبار تكامل: عميل CLI بسيط يتواصل مع الخدمة عبر IPC وينجح في إضافة/إيقاف تحميل.

## 9.9 v0.7 — Beta مغلق (Closed Beta)

**المهام المرتبطة:** 9.7، 9.9 - 9.13، إصلاحات أخطاء متنوعة تنتج من الاختبار الفعلي

**معايير الخروج:**
- [ ] صفر Critical Bugs مفتوحة.
- [ ] بناء ThreadSanitizer نظيف.
- [ ] تعليقات المختبرين الأساسية مُعالَجة أو مُوثَّقة كـ Known Issues.

## 9.14 v2.0 — الرؤية طويلة المدى (Major Features)

**تُقيَّم فقط بعد نضج حقيقي لـ v1.x ونمو مجتمع مساهمين كافٍ** — طموحة عمدًا ومرتبطة بالفصل 1 (§1.5 خارج النطاق):

| الميزة المحتملة | الاعتبار الهندسي |
|---|---|
| دعم BitTorrent/Magnet Links | يتطلب محرك مستقل تمامًا (libtorrent أو تنفيذ ذاتي) خارج نطاق `remo-core` الحالي بالكامل — على الأرجح Plugin منفصل وليس دمجًا في النواة |
| تطبيق موبايل مرافق (Remote Control) | يتطلب طبقة API/Server إضافية فوق `remo-service` (لم تكن مصممة أصلًا لهذا في SDS-03، تحتاج مراجعة معمارية) |
| مزامنة قائمة التحميلات عبر السحابة | قرارات خصوصية وبنية تحتية سحابية جديدة تمامًا (خارج فلسفة "محلي بالكامل" الحالية للمشروع) |
| دعم Linux رسمي | إعادة تقييم `platform/` abstraction layer (SDS-03 §3.7) لإضافة `platform/linux/` |
| Site Grabber (تحميل موقع كامل) | Plugin منفصل يستخدم Hook API من SDS-03 §3.8، وليس ميزة أساسية |

> **قرار استراتيجي متعمّد:** v2.0 غير مُخطَّطة بالتفصيل في هذه الوثيقة عمدًا، لأن التخطيط التفصيلي لميزات على بعد سنة أو أكثر، قبل حتى إطلاق v1.0، هو تخطيط وهمي يفتقر للمعلومات الحقيقية (حجم المجتمع الفعلي، الأداء الفعلي المُقاس، أولويات المستخدمين الحقيقيين بعد الاستخدام). القرار الصحيح هندسيًا هو إعادة فتح فصل SDS جديد (SDS-10: v2.0 Planning) بعد استقرار v1.0 فعليًا ببيانات استخدام حقيقية.
