# تعليمات البدء — مشروع Remoo Download

مرحبًا. أنت هتشتغل على تنفيذ مشروع **Remoo Download**، وهو مدير تحميل مفتوح المصدر (بديل لـ IDM) مبني بلغة **C++**، يستهدف Windows وmacOS.

## المرجع الكامل
مرفق ليك 9 ملفات (SDS-01 حتى SDS-09) تمثل وثيقة تصميم هندسي كاملة للمشروع:

| الملف | المحتوى |
|---|---|
| 01-Vision-and-Scope | الرؤية، النطاق، معايير النجاح |
| 02-IDM-Feature-Analysis-and-Redesign | كل ميزة مطلوبة بالتفصيل + كيفية بنائها |
| 03-Architecture | المعمارية الكاملة (الطبقات، المكونات، القرارات التقنية) |
| 04-Database-Design | مخطط قاعدة بيانات SQLite كامل بكل الجداول |
| 05-UI-UX-Design | تصميم الواجهة والشاشات |
| 06-UML-Diagrams | مخططات Class وSequence وState بصيغة Mermaid |
| 07-Code-Standards-Testing-CICD | معايير الكود، الاختبارات، CI/CD |
| 08-Task-Backlog | قائمة مهام مرقّمة بالأولوية (P0/P1/P2/P3) |
| 09-Release-Roadmap | خطة الإصدارات من v0.1 حتى v1.0 |

## طريقة العمل المطلوبة

**لا تحاول بناء المشروع كله دفعة واحدة.** اتبع الخطوات دي بالترتيب:

1. اقرأ **09-Release-Roadmap.md → قسم 9.3 (v0.1)** أولًا. ده أول إصدار مستهدف، وهو محرك تحميل أساسي (CLI فقط، بدون واجهة رسومية أو متصفح).

2. افتح **08-Task-Backlog.md** وابحث عن المهام المرتبطة بـ v0.1 (المذكورة في قسم 9.3): المهام من 1.1 إلى 1.8، ومن 2.1 إلى 2.9، و2.11، و2.24، و9.1 إلى 9.3.

3. نفّذ المهام **واحدة واحدة بالترتيب**، مش كلها مرة واحدة. كل مهمة فيها رقم مرجعي (مثال: `SDS-02 §2.2.2`) — ارجع لهذا القسم في الوثيقة المذكورة قبل ما تكتب أي كود، عشان تفهم التفاصيل الكاملة والقرارات المعمارية المطلوبة.

4. لأي تفاصيل معمارية أو تصميم داخلي (أسماء الأصناف، توقيعات الدوال، تدفق البيانات)، ارجع لـ **03-Architecture.md** و**06-UML-Diagrams.md** — دول المرجع الرسمي (Source of Truth) لأي كود بتكتبه.

5. لأي جدول أو استعلام قاعدة بيانات، ارجع لـ **04-Database-Design.md** بالضبط كما هو موثق — لا تبتكر مخطط جديد.

6. كل صنف جديد لازم يكون معاه **ملف اختبار وحدة (unit test)** على الأقل، حسب المعايير في **07-Code-Standards-Testing-CICD.md**.

7. بعد ما تخلّص كل مهام v0.1، ارجع لـ **09-Release-Roadmap.md → 9.3** وتأكد من تحقيق كل **معايير الخروج (Exit Criteria)** المكتوبة هناك قبل الانتقال لـ v0.2.

## قواعد مهمة
- لو لقيت تعارض بين الوثيقة والكود اللي هتكتبه، الوثيقة هي المرجع — اسألني قبل ما تنحرف عنها.
- لو مهمة معينة غامضة أو ناقصة تفاصيل، اسألني بدل ما تفترض.
- التزم بمعايير التسمية والتنسيق المكتوبة في 07-Code-Standards-Testing-CICD.md من أول سطر كود.

ابدأ بقراءة 09-Release-Roadmap.md (قسم 9.3) و08-Task-Backlog.md، وقولّي إيه أول مهمة هتبدأ بيها.
